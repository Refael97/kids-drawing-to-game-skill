# ציור ילדים → משחק

הופך צילום של ציור ילדים למשחק דפדפן אמיתי, שבו הדמויות והרקע הם החלקים מהציור עצמו (לא ציור מחדש). התוצאה: קובץ HTML אחד שעובד בלי אינטרנט, מתאים לילדים בני 3–8, ועובד במחשב, בטלפון ובטלוויזיה (שלט = חיצים).

הרגע שהופך את זה למיוחד: הילד רואה את **הדמות שהוא צייר** זזה על המסך. לכן תמיד גוזרים את האלמנטים מהתמונה, ומציירים מחדש רק כשאין ברירה.

## שלב 1 – לקרוא את הציור

1. מסתכלים על התמונה ורושמים כל אלמנט: דמויות/חיות, חפצים, רקע (שמש, עננים, דשא, מים, בית, עצים).
2. לכל אלמנט מעריכים bounding box בפיקסלים של התמונה המקורית (x0,y0,x1,y1) ואת הצבעים הדומיננטיים שלו.
3. בוחרים **דמות ראשית אחת** – בדרך כלל חיה או דמות. היא השחקן.
4. בוחרים **מכניקה אחת** שנובעת מהציור:
   - עץ עם פירות → אוספים פירות שנופלים
   - מים + דג → קופצים לתפוס את הדג שקופץ
   - שמיים + ציפור/מטוס → עפים בין עננים ואוספים כוכבים
   - בית/דלתות → מוצאים דברים מוסתרים
   - כביש/מכונית → נוסעים ומתחמקים בעדינות (בלי התנגשות שפוסלת)
   אפשר לשלב מכניקה ראשית + בונוס אחד (למשל: תפוחים = 1, דג = 5).
5. כותבים למשתמש בשתי שורות מה יהיה המשחק, וממשיכים מיד (לא מחכים לאישור אלא אם ביקש).

## שלב 2 – לגזור את האלמנטים מהתמונה (Python + PIL)

רקע הדף לבן/אפור בהיר. תוכן = רוויה גבוהה או כהה. לכל אלמנט בונים מסכה, ומוציאים ממנה צבעים של אלמנטים שכנים שנכנסו לקופסה.

```python
from PIL import Image, ImageFilter
import numpy as np
im = Image.open('drawing.png').convert('RGB'); a = np.asarray(im).astype(int)
r, g, b = a[...,0], a[...,1], a[...,2]; mx = a.max(2); mn = a.min(2); sat = mx - mn
H, W = mx.shape; yy, xx = np.mgrid[0:H, 0:W]
base   = (sat > 45) | (mx < 120)            # כל מה שאינו נייר
green  = (g > r + 15) & (g >= b)
blue   = (b > r + 25)
lblue  = blue & (mx > 170)                    # תכלת (עננים, מים)
yellow = (r > 200) & (g > 180) & (b < 150)
orange = (r > 170) & (g > 70) & (g < 200) & (b < 130)

def cut(name, box, m):
    x0, y0, x1, y1 = box
    mm = m[y0:y1, x0:x1].astype('uint8') * 255
    al = Image.fromarray(mm).filter(ImageFilter.MaxFilter(3)).filter(ImageFilter.GaussianBlur(0.8))
    rgba = im.crop(box).convert('RGBA'); rgba.putalpha(al)
    bb = rgba.getbbox(); rgba = rgba.crop(bb); rgba.save(name + '.png')
    print(name, rgba.size, 'placed at', (x0 + bb[0], y0 + bb[1]))   # המיקום בעולם המשחק
```

דוגמאות למסכות נכונות:
- חתול שחור שעומד על דשא: `base & ~green` (אחרת הדשא נגזר איתו)
- הדשא: `base & ~blue & ~catzone` – להוציא את הרגליים של הדמות, אחרת נשארים "רגליים רפאים" על הדשא
- דג כתום בתוך מים: `orange | (dark & ~blue)`
- שמש ליד גג כתום: `base & ~roofzone`, כש־roofzone הוא מלבן של `xx`/`yy` סביב הגג
- עץ שקרן שמש נכנסת לקופסה שלו: `base & ~yellow`
- בית שחתיכת ענן נכנסה לפינה שלו: `base & ~green & ~lblue`

**חובה לבדוק:** מרכיבים את כל הגזירות על רקע כהה לתמונה אחת, ומסתכלים עליה. מחפשים: חלקים חתוכים (להגדיל את הקופסה), שאריות של אלמנט שכן (להוסיף החרגה), ונקודות זבל. מתקנים ובודקים שוב. שומרים את המיקום (x,y) של כל גזירה – בעולם המשחק כל אלמנט עומד בדיוק איפה שהיה בציור.

אם אין גישה לקובץ התמונה (למשל צ׳אט בלי הרצת קוד): מציירים את האלמנטים ב־canvas בסגנון צבעי שעווה (כמה שכבות שקופות עם רעד קטן), באותם צבעים, צורות ומיקומים.

## שלב 3 – לבנות את המשחק

קובץ HTML אחד. הגזירות נכנסות כ־data URI (עדיף WEBP באיכות 88 – מקטין פי 4 לעומת PNG). עולם קבוע בגודל התמונה המקורית (למשל 1000×563) שמוקטן ל־canvas, כך שכל המיקומים מהגזירה עובדים כמו שהם.

**כללי ילדים (לא לשבור):**
- בלי פסילה, בלי "הפסדת", בלי חיים שנגמרים. מה שלא נתפס נוחת, קופץ קצת ונעלם.
- סבב של 60 שניות → מסך "כל הכבוד!" עם קונפטי, הניקוד במילים ("אספת 23 נקודות ותפסת 2 דגים!") וכפתור "עוד פעם!".
- קצב איטי שמתגבר קצת עם הזמן.
- צלילים קצרים ושמחים ב־Web Audio (אין קבצי סאונד). אודיו מתחיל רק אחרי לחיצה.
- טקסטים בעברית, גדולים. כפתור התחלה גדול ובולט עם פוקוס, כדי ש־Enter בשלט יתחיל.

**שליטה:**
- מקלדת/שלט: חיצים לזוז, רווח / חץ למעלה / Enter לקפוץ.
- טלפון וטאבלט: שלושה כפתורים גדולים מתחת למשחק (◀ · קפיצה · ▶), עם pointerdown/pointerup כדי שהחזקה תזיז. מוסתרים במחשב עם עכבר.
- נגיעה בציור עצמו: בצד של הדמות = זז לשם, על הדמות = קפיצה.

**חיים בציור:** השמש מתנדנדת קצת וגדלה כשתופסים משהו, העננים זזים לאט, הדמות הופכת כיוון לפי התנועה ומקפצת בהליכה, "+1" צף מעל כל תפיסה. לכבד prefers-reduced-motion.

**מראה הדף:** רקע שולחן בז׳, המשחק על "דף" קרם עם צל רך, פונטים Secular One (כותרות) ו־Rubik מ־Google Fonts. HUD בפינות (ניקוד, זמן) שמוסתר כשמסך פתיחה/סיום פתוח. להוסיף `[hidden]{display:none!important}` כי overlay עם display:grid דורס את hidden.

## שלב 4 – לבדוק

עם Playwright: לפתוח את הקובץ במחשב (1280×800) ובטלפון לרוחב, ללחוץ "התחל", להזיז את הדמות כמה שניות, ולוודא שהניקוד עולה, הזמן יורד, אין שגיאות קונסול ואין גלילה לרוחב. צילום מסך אחד באמצע משחק – ולבדוק שאין שאריות גזירה על המסך.

## שלב 5 – למסור

- לפרסם את המשחק כ־artifact (שאפשר לפתוח ולשחק מכל מכשיר), או למסור את קובץ ה־HTML אם ביקשו קובץ.
- להסביר בשורה איך משחקים ובאיזה שליטה.
- אם צריך תוכן לרשתות: להקליט משחק אוטומטי עם Playwright (`recordVideo`, ו"טייס אוטומטי" שמזיז את הדמות לעבר הפריט הקרוב וקופץ כשהבונוס עובר מעליה), ולהמיר ל־MP4 עם ffmpeg (`-c:v libx264 -preset veryfast -crf 20 -pix_fmt yuv420p`). לצרף את הגזירות כ־PNG שקופים – עורך הווידאו יכול "להוציא" את הדמות מהדף.
- אם הציור נראה כמו תמונת סטוק ולא ציור אמיתי של ילד, לציין את זה (זכויות שימוש, ושלא כדאי לכתוב בתוכן "הילד שלי צייר").
